# ADR-002: Pure Utility Functions vs Repository Pattern for SEO & Metadata

## Status

Accepted

## Date

2026-07-28

## Context

The Levemente AI codebase utilizes Clean Architecture with Singleton Repositories (`RepositoryFactory`, `ServiceFactory`). However, Next.js 16 App Router executes `generateMetadata()`, `sitemap.ts`, `robots.ts`, and React Server Components (RSC) natively on the server during build (SSG) and request time. Coupling server-side SEO generation to stateful client/server repositories creates unnecessary overhead and potential hydration/serialization edge cases.

## Decision

We will implement SEO utilities, dynamic metadata builders, JSON-LD schema generators, and OpenGraph link helpers as pure, side-effect-free functions under `utils/seo/`. These functions will accept domain inputs (e.g., term strings, meal entity structures, locales) and return immutable metadata/JSON-LD objects directly compatible with Next.js `Metadata` types.

## Alternatives Considered

### Alternative 1: Stateful `SeoMetadataRepository` with Singleton Pattern

- **Description**: Wrap all metadata generation inside a singleton repository pattern registered in `RepositoryFactory`.
- **Pros**: Maintains strict uniformity with entity data access patterns.
- **Cons**: Adds unnecessary class boilerplate for stateless string/object transformations and risks bundle bloat in Server Components.
- **Why rejected**: User explicitly requested pure utility functions in `utils/seo/` for lightweight, deterministic execution.

## Consequences

### Positive

- Zero side-effects and instant execution during Next.js SSG build and RSC evaluation.
- Highly testable unit functions with straightforward input/output assertions.
- Keeps client/server bundle size minimal.

### Negative

- Differs slightly from repository abstraction used for persistent data entities.

### Risks

- Utility functions must remain pure without direct fetch calls to un-cached external resources.
- Mitigation: Pass resolved domain entities into utilities rather than executing database calls inside `utils/seo/`.
